1. APP ARCHITECTURE OVERVIEW
====================================================================
- Flutter app in soko_langu/lib/; server in soko_langu/server/.
- Auth: Firebase Auth (email/password, magic link, Google, PHONE OTP via
  server /api/auth/* — custom, NOT Firebase Phone Auth).
- Data: Firestore (collections list katika sehemu ya 24).
- Payments: ClickPesa (escrow, USSD Push, BillPay, payouts, webhooks).
- Push: OneSignal + Firebase Cloud Messaging fallback topic user_{uid}.
- SMS: Meseji.co.tz (sender SOKOVIBE default, fallback MESEJI).
- Server modules: index.js (Express, ~7300 lines), clickpesa.js, orders.js,
  listener.js (Firestore listeners), notification.js, groq.js, search.js.

7. ORDER LIFECYCLE (STATE MACHINE)
====================================================================
Statuses (server/orders.js ORDER_STATUS):
  pending → awaiting_shipping_quote → quoted → paid → paid_escrow_hold
  → escrow_hold → dispatched → delivered → delivery_confirmed → completed
  → failed → refunded → disputed (na invalid/nafuu za transition).

7.1 Buyer flow:
  1. pending: order imeundwa. /api/orders/create pia inamirror transactions/
     {orderId} na status 'awaiting_shipping_quote' — mnunuzi HANA kitufe cha
     kulipa hadi seller aweke gharama (pay button inatokea tu kwenye 'quoted').
  2. awaiting_shipping_quote: mnunuzi anangoja seller aweke gharama ya
     usafirishaji (order detail: "Subiri muuzaji kutoa gharama ya usafirishaji";
     My Purchases: kitufe "Inasuburi Gharama ya Usafirishaji" disabled).
  3. quoted: seller ameweka shippingCost (totalAmount += shippingCost);
     mnunuzi ana options: pay (wallet/ussd/billpay), cancel.
  4. paid/escrow_hold: malipo yametumwa kwenye escrow ya ClickPesa.
  5. dispatched: seller amesafirisha (proof: tracking, receipt, photo,
     busName, plateNumber) → mnunuzi anaona RealtimePaymentBanner +
     countdown ya estimatedDelivery.
  6. delivery_confirmed: mnunuzi anathibitisha kupokea (Thibitisha
     Upokeaji) → escrow release.
  7. completed: escrow imetolewa kwa seller (sellerBalance += sellerReceives).

7.2 Seller flow (seller_orders_screen.dart, seller_quote_screen.dart):
  1. Inapokea order (tx doc status 'awaiting_shipping_quote') → quote inaweka
     status 'quoted' kwenye DOCUMENTS ZOTE MBILI:
     - transactions/{orderId}: shippingCost + totalAmount += shippingCost +
       status 'quoted' (seller_quote_screen inaandika moja kwa moja Firestore;
       seller_orders_screen quote dialog inafanya set(merge) baada ya
       transition).
     - orders/{orderId}: POST /api/orders/transition {newStatus:'quoted',
       note:{shippingCost}} — inaandika timeline + inamjulisha mnunuzi
       ("Gharama ya Usafirishaji Imewekwa! Lipa sasa").
  2. Dispatch: server POST /api/escrow/dispatch (transactions/{orderId};
     status lazima escrow_hold; inaweka dispatchProof, busName,
     plateNumber) → SMS + push kwa buyer.

7.3 Escrow release: POST /api/escrow/release (buyer, status dispatched):
  - transactions doc: status delivered, escrowReleased=true,
    sellerBalance += sellerReceives, pendingEscrow -=, revenue_transactions
    + auditLog; SMS + push.
  - optional auto-payout kama seller.autoPayout === true.

7.4 Cancel (buyer, kutoka escrow_hold/paid_escrow_held):
  - Refund = productPrice − DEFAULT_PAYOUT_FEE (TZS 2,000) kupitia ClickPesa
    payout kwa namba ya buyer; status refunded; seller pendingEscrow/
    totalSales/grossSalesVolume zina-punguzwa.

7.5 Dispute: mtumiaji anaweka dispute → server POST /api/escrow/dispute
  (status disputed) → admin: POST /api/escrow/admin-resolve-dispute
  (resolution 'release' → delivered + sellerBalance; au 'refund' →
  ClickPesa payout productPrice + penalties kwa seller + revenue_transactions).

7.6 Auto-release: POST /api/release-expired-escrows (admin/cron tu) —
  escrow_hold + escrowExpiresAt ≤ now. Pia POST /api/cron/release-escrows
  (x-cron-secret).

7.7 Payment status watcher: TransactionStatusWatcher (overlay) +
  RealtimePaymentBanner ina-poll GET /api/transaction-status/:orderId kila
  sekunde 7 + StreamBuilder kwenye transactions doc.

7.8 FAILED: status failed → mnunuzi anaweza retry
  (server /api/retry-payment au legacy webhook handling).

NOTE (discrepancy): my_purchases_screen inaita POST /api/dispute/create
(l.341) lakini server ina /api/escrow/dispute tu — dispute kutoka client
inge-404.

NOTE: wallet purchase inaunda transactions doc MPYA (auto-id) na field
`orderId` ikirejelea order doc; client pia inaita _transitionOrder('paid')
kwenye orders/{orderId} — inaweza kuleta duplicate kwenye My Purchases
(streams transactions where buyerId==uid).

8. PAYMENTS (ClickPesa) — FLOWS ZA MALIPO
====================================================================
8.1 USSD Push collect (malipo ya order / deposit / boost):
  1. Client inapiga endpoint (mf. POST /api/orders/create,
     /api/wallet/deposit, boost) na paymentMethod 'ussd_push'.
  2. Server inahesabu processingFee = getUssdPushFee(amount) (tiers) →
     totalCharge = amount + fee.
  3. clickpesaCollect({amount, orderReference, phoneNumber (255...),
     callbackUrl: /api/clickpesa/webhook}) → ClickPesa inatuma USSD prompt
     kwenye simu ya mteja; server inarudi mapema (async).
  4. Mteja anapiga PIN → ClickPesa inapiga webhook.
  5. transactions doc: clickpesaReference, ussdSent:true; webhook
     ina-update status (escrow_hold etc.).
  6. Failures: ussdFailed:true + ussdError; buyer anaweza retry; stale
     pending boost payments zina-fail baada ya muda (cron).

8.2 BillPay (control number):
  1. Server inaunda BillPay order (clickpesaCreateBillPayOrder,
     billPaymentMode EXACT, billReference=orderId).
  2. Inarudisha billPayNumber → app inaonyesha kwenye waiting sheet pamoja
     na button ya COPY (Icons.copy → Clipboard, snackbar 'Imenakiliwa').
  3. Mteja anaenda M-Pesa > Lipa > BillPay, anaingiza namba na kiasi
     (totalCharge = amount + 1%).
  4. Webhook ina-confirm → status escrow_hold/completed.

8.3 Wallet purchase: order_detail method='wallet' → kuna balance check →
  transactions doc mpya escrow_hold + order transition 'paid'.

8.4 Webhook (POST /api/clickpesa/webhook) inashughulikia:
  - deposits (orderReference prefix 'dep') → users.walletBalance += .
  - purchases → escrow_hold + platformFee (3.5% ya price) + processingFee
    (USSD tier) + sellerReceives = price + shipping.
  - flash_sale → stock/soldCount decrement.
  - boost → activation ya boost.

8.5 Transaction status: GET /api/transaction-status/:orderId (fallback
  ikitokea webhook kukosa).

8.6 Payment methods: GET /api/payment-methods, POST /api/payment-methods/calc-fee
  (wallet/ussd_push/billpay).

8.7 Fraud/prevention: paymentRateLimit, checkSuspended, checkDuplicatePayment,
  checkDailyLimit (MAX_DAILY_SALE_AMOUNT) kwenye create-marketplace-payment-link.
