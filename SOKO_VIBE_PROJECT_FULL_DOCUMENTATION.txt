0. MUHTASARI WA HARAKA (EXECUTIVE SUMMARY)
================================================================================

Soko Vibe ni marketplace ya mtandaoni ya Tanzania inayounganisha wanunuzi na
wauzaji wa bidhaa halisi (physical goods) kwa modeli ya "trust commerce":
malipo yanashikiliwa kwenye escrow, bidhaa inatumwa, mnunuzi anathibitisha
kupokea kwa OTP/QR, kisha seller analipwa. Jukwaa linajenga trust kupitia
utambulisho (KYC), Blue Tick, trust passport, reviews, dispute resolution na
ulinzi wa mnunuzi.

Muundo wa mfumo (high level):

  Flutter app (Android/iOS/Web/Desktop)
        |
        | HTTPS  https://api.sokovibe.co.tz
        v
  Cloudflare Worker "soko-api-edge"  (cache + proxy + edge security)
        |
        v
  Node.js/Express API (Render, region Frankfurt, plan free)
        |            |              |
        |            |              +--> Redis (rate limit, locks, BullMQ, OTP)
        |            +------------------> AzamPay (collections + payouts)
        +-------------------------------> Firestore (source of truth)
                                         |
                                         +--> Firebase Auth / App Check
                                         +--> OneSignal (push)
                                         +--> Meseji / Notify Africa (SMS)
                                         +--> WhatsApp Cloud API (OTP)
                                         +--> Cloudflare R2 (media, KYC docs)
                                         +--> Groq / Gemini / Workers AI (AI)

Sifa kuu zilizopo kwenye code:
- App ya Flutter yenye screen 87 na service 97+ (lib/), iko tayari kwa
  Android, iOS, Web, Windows, macOS, Linux.
- Lugha mbili: Kiswahili (sw) na English (en); currency 9.
- Auth: email/password, Google Sign-In, phone OTP, email OTP, MFA (TOTP),
  app lock kwa PIN/biometric, logout-all (session revocation).
- Marketplace: feed, search (v1 API + Firestore fallback), categories,
  discovery filters, wishlist, recently viewed, buyer requests, flash sales.
- Uuzaji: kuunda bidhaa, media upload moja kwa moja R2, publish/unpublish,
  moderation, boost/ads, seller analytics, subscriptions.
- Manunuzi: order state machine kamili, shipping quote, escrow payment kwa
  AzamPay, dispatch, delivery, OTP/QR handover, auto-release.
- Fedha: wallet ya seller, ledger isiyobadilika, withdrawal state machine,
  refunds, disputes na split resolution, reconciliation, audit logs.
- Jamii: chat 1:1 na group, reactions, typing, status, follow/block,
  comments na replies.
- AI: assistant wa Soko Vibe (Groq -> Gemini -> Cloudflare AI failover),
  persistent chat na memory, voice replies, agent yenye tools na
  ruhusa/approvals.
- Admin: static browser panel (admin.js ~3,192 mistari) + Flutter admin
  screens + staff console + Company OS UI.
- Infra: Cloudflare edge cache, R2 media worker, AI edge worker, Firebase
  App Check, Cloudflare Turnstile kwenye public forms.

1. BIDHAA, SOKO NA MODELI YA BIASHARA
================================================================================

1.1 Taswira ya bidhaa
Soko Vibe ni "soko la kidijitali la Tanzania" lenye mwelekeo wa kuaminiana.
Mtumiaji anaweza kuwa:
- Buyer (mnunuzi): anatafuta, anaangalia, anachat na seller, analipa kwa
  escrow, anafuatilia oda, anathibitisha kupokea, anaacha review.
- Seller (muuzaji): anaomba seller mode, anaweka bidhaa, anapokea oda,
  anatoa shipping quote, anasafirisha, anapokea malipo kwenye wallet.
- Admin / staff: wanasimamia watumiaji, bidhaa, oda, migogoro, refunds,
  KYC, withdrawals, banners, matangazo, settings na audit.
- Company member (Company OS): mtazamo wa shirika (legal entities, audit,
  settings) - UI ipo, backend routes zipo lakini hazijamountiwa (Section 16).

1.2 Value proposition
- Escrow: pesa haitoki kwa seller mpaka mnunuzi athibitishe kupokea.
- OTP/QR handover: uthibitisho wa makabidhiano upo kwenye mfumo, si kwa
  mazungumzo ya nje.
- Trust passport: seller anapata alama za uaminifu (fulfilment, disputes,
  verification, reviews).
- Blue Tick: uthibitisho wa seller unaoonekana kwenye profile na bidhaa.
- Dispute resolution yenye ushahidi na split ya escrow.
- Multi-channel notifications: push, SMS, WhatsApp, email, in-app.
- AI assistant wa kununua/kuuza kwa Kiswahili.

1.3 Modeli ya mapato (kwa mujibu wa code ya sasa)
- Platform commission default ni 0%. `computeSellerParity()` inarudisha
  commission 0 na seller anapata productPrice + shippingFee kamili.
- Commission inaweza kuwekwa kwa `PLATFORM_COMMISSION_PERCENT` (config) au
  admin settings (`paymentsAndCurrency.platformCommissionPct`); admin field
  inakubali 3.5 au 0.035 (coin ya juu ya 1 inachukuliwa kama percent).
- Ada za gateway (AzamPay collection/payout) zinakatwa na AzamPay nje ya
  ledger ya Soko Vibe; haziongezwa kwenye totalAmount ya mnunuzi.
- Mapato mengine yanayopatikana kwenye code: boost/ads packages, flash sale
  promotion, seller subscriptions (Seller Plus 14,900 TZS/mwezi, Seller Pro
  29,900, Business 79,900), KYC verification fee 15,000 TZS (one-time),
  ad revenue (AdMob), referrals.
- HATARI: docs za zamani zinasema "commission 3.5%". Code ya sasa haitumii
  3.5% kama default; 3.5% ni legacy/thamani inayoweza kuwekwa.

1.4 Watumiaji na majukumu (roles)
- buyer (default)
- seller (baada ya seller profile)
- admin / super_admin (isAdmin flag kwenye users)
- staff (admin panel staff accounts)
- company_member (Company OS; RBAC kwa permissions)
- system (jobs, webhooks, auto-release)

1.5 Kanuni za msingi za biashara
- Server ndiyo mamlaka ya bei na stock; client haiaminiki kwa totalAmount.
- Order haiwezi kulipwa mpaka shipping quote ikubaliwe.
- Escrow release inatokea tu kwenye state COMPLETED (au dispute ruling).
- Pesa haiwezi kutoka wallet bila ledger entry (idempotent key).
- Withdrawal haiwezi kuanza bila reservation ya fedha.
- Disputed escrow hairuhusiwi auto-release.
- OTP haitumwi kwenye push payload; push ni ping tu.
- KYC documents haziko kwenye bucket ya public media.

1.6 Taratibu za lugha na eneo
- App languages: sw, en.
- Currency: TZS, USD, EUR, GBP, KES, UGX, NGN, ZAR, CNY.
- Timezone ya biashara: Africa/Dar_es_Salaam.
- Nchi ya default ya address: TZ.
- Districts za Tanzania ziko `lib/constants/tanzania_districts.dart`.

4. FRONTEND ARCHITECTURE (FLUTTER APP)
================================================================================

4.1 Boot sequence (`lib/main.dart`)

Mpangilio halisi wa kuanzisha app:

1. `WidgetsFlutterBinding.ensureInitialized()`.
2. Image cache cap: `PaintingBinding.instance.imageCache.maximumSizeBytes =
   200 * 1024 * 1024` (200 MB) - kuzuia OOM kwenye simu ndogo.
3. `themeManager.load()` - theme mode/preferences.
4. `SafeTextFilter.init(language: Language.swahili)` - profanity filter.
5. `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)`
   kwa timeout 15s. Kwenye native: Firestore settings
   `persistenceEnabled: false` - app ni ONLINE-ONLY kwa Firestore ili
   data ya cache isionekane kama authoritative; offline inashughulikiwa na
   Hive/local cache tofauti.
6. `LocalCacheService.init()` (Hive; timeout 20s; inafanya kazi pia web
   kupitia IndexedDB).
7. `PlatformConfigService.instance.loadCommissionRate()` (fire-and-forget).
8. Global error handlers (native only): FlutterError -> Crashlytics +
   ErrorReportingService; PlatformDispatcher.onError -> Crashlytics fatal.
9. `GoogleSignIn.instance.initialize()` (native, timeout 10s).
10. `LocalNotificationService().initialize()` (native).
11. `initSokoMediaAudio()` (audio_service background playback; native).
12. `runApp(const SokoVibeApp())`.

Ndani ya `SokoVibeApp.initState()`:
- `NetworkStateService().start()` - connectivity truth moja.
- `ProductFeedProvider(repo: ProductRepository(networkState))`.
- `AuthRepository()`, `OnboardingService()`, `AuthNotifier(...)`.
- WidgetsBinding observer; theme listener; appState listener.
- `_initApp()` (async): SharedPreferences; language default `sw`;
  currency default TZS; `authNotifier.initialize()`; sync language to
  Firestore; `appStateNotifier.setAppInitialized()`; session tracking;
  `DeepLinkService.flushPending()`; phone sync; `AppLockService.load()`;
  notification callbacks; artwork pack init; banner service start;
  background services.
- `_setupNavigateChannel()` - Android MethodChannel `soko_lang/navigate`.
- `_setupDeepLinks()` - `DeepLinkService` + app_links.
- `_setupShareReceive()` - `ReceiveShareService` (share media into sell
  composer).

Background services (`_initBackgroundServices`):
- Crashlytics collection enabled.
- Performance collection enabled.
- App Check: Android Play Integrity (debug: AndroidDebugProvider), Apple
  DeviceCheck; debug token inaprintiwa.
- `SecurityService().initialize()` - root/jailbreak detection.
- `notificationService.initialize()` - OneSignal + in-app.
- `ExchangeRateService().initialize()` - multi-currency display.
- `AiService.initialize(GroqService())`.
- `ServerKeepAlive.instance.start()` - inawasha Render free tier.

4.2 App shell na overlays

`MaterialApp.router` ina:

4.3 Routing na guards

Router: `lib/app/router.dart` (`buildRouter()`), `GoRouter` yenye:
- `navigatorKey: rootNavigatorKey`
- `initialLocation: AppRoutes.home` (`/`)
- `refreshListenable: app_state.appStateNotifier`

Guard logic (kwa mpangilio):
1. Kama app haijaanza (`!appInitialized`) -> ruhusu (splash).
2. Kama onboarding imechunguzwa na haijakamilika -> kurasa zote isipokuwa
   onboarding, login, register, forgot-password, privacy, terms,
   otp-verification, verify-email zinapelekwa `/onboarding`.
3. Kama onboarding imekamilika na uko `/onboarding` -> `/`.
4. Kama umeingia na uko login/register -> `/`.
5. Admin-only routes: kama haujaingia -> `/login`; kama si admin -> `/`.
6. Auth-required routes: kama haujaingia -> `/login`.

`_adminOnlyRoutes` na `_authRequiredRoutes` zinafafanua routes
zinazolindwa. Admin anaamuliwa na `appStateNotifier.isAdmin` ambao
unatokana na `users/{uid}.isAdmin == true` (si email).

4.10 Media pipeline

Upload (bidhaa/profile/KYC):
1. Client inaomba presigned URL: `POST /api/v1/media/upload-url`
   (authenticated) na metadata (kind, contentType, ownerType, size).
2. Server inaunda key: `<kind>s/<ownerType>/<ownerId>/<uuid>.<ext>`
   (mfano `images/product/<uid>/<uuid>.webp`).
3. Client inapakia bytes moja kwa moja R2 kwa PUT (progress callbacks).
4. Client inahifadhi public URL (`https://media.sokovibe.co.tz/...`)
   kwenye product/profile.
5. `soko-media` worker inasoma first path segment (`images/`, `videos/`,
   `thumbnails/`, `backups/`, `artwork/`) na kuchagua bucket.
6. KYC documents: bucket `soko-vibe-kyc` haiko bound kwenye worker;
   read tu kwa presigned GET ya muda mfupi baada ya authorization.

Client media services:
- `R2MediaService`: upload picha/video/avatar/kyc, batch upload,
  progress.

  destroy tu kwa cleanup).
- `ImageCompressor` (`utils`): compression kabla ya upload.

- `Audio`: `just_audio` + `audio_service` (background playback,
  notification controls); `AiVoicePlayer`; `MediaAudioHandler`.
- `Video`: `video_player`, `ProductVideoPlayer`.
- Receipts: `ReceiptPdfService` (pdf + printing) na `receipt` screen.

7. BACKEND ARCHITECTURE (NODE.JS / EXPRESS)
================================================================================

7.1 Boot sequence (server)

Faili kuu: `server/src/index.js`, `server/src/app.js`.

1. `src/index.js` inaita `dotenv.config()` kabla ya module nyingine.
2. Inaunda Express app kwa `createApp()`/`app` na kusikiliza `PORT` (default
   3000). Production inatumia `node --optimize-for-size --expose-gc`.
3. `initialize()` inaunganisha Firestore Admin (`connectDatabase`) na Redis
   (`connectRedis`). Firestore ni store ya lazima; Redis ni best-effort
   (cache, rate limit, OTP, queues) - ikikosekana, baadhi ya features zinashuka
   salama.
4. Inaanzisha finance worker ndani ya process kama
   `FINANCE_WORKER_IN_PROCESS !== 'false'`, na `scheduleFinanceJobs()`.
5. Inaandika startup log yenye providers za AI, persistent chat na agent.
6. Process signals (SIGTERM/SIGINT) zinafunga queues/worker kwa graceful
   shutdown.

Tabia muhimu:
- `BigInt.prototype.toJSON = Number` - TZS hutumia BigInt/Decimal; JSON
  haitishi BigInt.
- `app.set('trust proxy', 1)` - IP halisi ni ya client nyuma ya Cloudflare
  Worker + Render.
- Production inakataa kuanza bila `APP_URL`, `AZAMPAY_COLLECTION_WEBHOOK_URL`
  na `AZAMPAY_CALLBACK_PASSWORD` (fail fast).

7.2 Express middleware pipeline (kwa mpangilio halisi)

1. `express-async` patch - async route rejections zinaenda kwenye error handler
   badala ya kunyongwa hadi 504.
2. `loadShedder()` - kwanza kabisa; inarudisha 503 mapema event loop/heap
   ikizidiwa.
3. `requestId` - inachukua `x-request-id` ya edge au `crypto.randomUUID()`;
   inaweka header na kuongeza `requestId` kwenye kila JSON response.
4. `compression()` - gzip.
5. Security headers: `X-Content-Type-Options`, `X-Frame-Options: DENY`,
   `X-XSS-Protection`, HSTS, `Referrer-Policy`, CSP (CDN allow-list kwa
   landing/admin), `Permissions-Policy`.
6. URI length guard - zaidi ya 8 KiB => 414 `REQUEST_URI_TOO_LONG`.
7. API hit counter - `recordApiHit()` kwa path `/api*` (fire-and-forget,
   Redis-backed).
8. Canonical host middleware:
   - `www.sokovibe.co.tz` ni host rasmi.
   - apex `sokovibe.co.tz` inarudishwa 301 www, isipokuwa `SERVE_APEX=1`.
   - `admin.sokovibe.co.tz` inaandika upya path kwenda `/admin` static panel.
   - `api.sokovibe.co.tz` haigusi (edge worker).
   - subdomain nyingine zinafoldiwa www.
9. HTTPS-only redirect kwa domain halisi.
10. Trailing-slash normalization (301) kwa public pages; `/api`, `/health`,
    `/.well-known`, `/admin` haziguswi.
11. CORS - origin allow-list kutoka `ALLOWED_ORIGINS`, methods 6, headers
    `Authorization`, `x-admin-secret`, `x-admin-totp`; credentials false.
12. `express.json({ limit: '1mb' })` - hakuna bytes za media kwenye JSON.
13. Request timeout - `res.setTimeout(20000)` => 504 `REQUEST_TIMED_OUT`;
    `_startTime` inarekodiwa.
14. App Links/Universal Links: `/.well-known/assetlinks.json`,
    `apple-app-site-association` (JSON content-type).
15. SEO router: `robots.txt`, `sitemap.xml`, meta/OG routes.
16. Public HTML pages (15): `/about`, `/about/founder`, `/how-it-works`,
    `/features`, `/buyers`, `/sellers`, `/pricing`, `/faq`, `/contact`,
    `/privacy`, `/terms`, `/cookies`, `/data-deletion`, `/waitlist/success`,
    `/unsubscribe` - `no-cache`, `406` kama client haikubali HTML.
17. Legacy path redirects (301): `/how-soko-vibe-works`, `/soko-vibe-fees`,
    `/soko-vibe-escrow`, `/support`, `/privacy-policy`, `/terms-of-service`,
    `/tanzania-marketplace`, `/categories`.
18. Legacy `.html` redirects (301) kwenda clean URLs.
19. `/marketing` na `/shop` => 301 `/`.
20. `/admin` static panel; `/admin.html`, `/dashboard`, `/admin/index.html` =>
    301 `/admin/`.
21. Landing static (`server/landing`): HTML/manifest `no-cache`; assets
    versioned `immutable`; favicons `no-cache`; `/favicon.ico` redirect.
22. Deep-link fallback router (`sharing/fallback-routes`) kabla ya static.
23. Rate limiter: `/api/v1` general; `/api/v1/admin` admin; AI own limiters.
24. Module mounts (Section 7.3).
25. 404 handler: JSON envelope kwa `/api` na `/health`; branded `404.html` kwa
    HTML; `text/plain` kwa wengine.
26. Error handler: structured JSON log yenye `requestId`, method, path, status,
    errorName, message, durationMs, code; `Retry-After: 5` kwa
    `LOCK_UNAVAILABLE`/`REDIS_UNAVAILABLE`; production message generic.

7.9 Error handling na API envelope

Mafanikio (mara nyingi): `{ success: true, data: ... }` au payload ya module.
Makosa: `jsonError()` inarudisha:

```
{
  "success": false,
  "data": null,
  "error": "CODE",
  "code": "CODE",
  "message": "Human readable",
  "requestId": "uuid",
  "details": ...   // optional
}
```

- `error` ni string code ya zamani (clients za zamani zinaiparse).
- `requestId` inarudi kwenye header `x-request-id` na kwenye body.
- Status za kawaida: 400 validation, 401 auth, 403 permission/role, 404,
  409 conflict/state, 422 business rule, 429 rate limit, 500, 503 overload,
  504 timeout.
- Production haitoi stack wala message za ndani; dev inaonyesha message halisi.
- Logs ni JSON zenye requestId, durationMs na code; hii ndiyo inayotumika
  kwenye support na monitoring.

8.0 Misingi ya API

- Base URL ya production: `https://api.sokovibe.co.tz` (mbele yake Cloudflare
  Worker `soko-api-edge`); origin ya Render pia inaweza kuhudumia moja kwa moja.
- API version: `/api/v1` kwa surface mpya; `/api/*` ni legacy/compat kwa apps
  za zamani na web shop; `/api/ai` na `/api/agent` zina shape yao.
- Auth: `Authorization: Bearer <Firebase ID token>`. Admin routes zinaongeza
  `x-admin-secret` na `x-admin-totp` (admin ya KYC inatumia database-verified
  admin role).
- Content-Type: `application/json`; ukubwa wa juu 1 MB.
- Success envelope: `{ "success": true, "data": ... }` au payload ya module.
- Error envelope: Section 7.9. Kila response ina `x-request-id`.
- Pagination: `limit`/`take`, `cursor`/`startAfter`, `skip`; modules zinarudisha
  `{ items, nextCursor }` au `{ data, pagination }`.
- Idempotency: payments (`idempotencyKey`), webhooks (`dedupKey`), wallet ledger
  (`idempotencyKey`), withdrawals (`idempotencyKey`).
- Rate limits: Section 7.5.
- Tarehe: ISO 8601; pesa: integer TZS (BigInt/Decimal nyuma ya pazia).

10. MONEY MODEL (ORDER, ESCROW, WALLET, COMMISSION, REFUNDS)
================================================================================

10.1 Kanuni za msingi

- Currency ya msingi: TZS; integer only.
- `totalAmount = productPrice + shippingFee` (kwa kiasi cha bidhaa moja kwa
  mzunguko wa kawaida).
- Commission ya jukwaa: **0 kwa default** (`computeSellerParity`), inaweza
  kuwekwa kwa `PLATFORM_COMMISSION_PERCENT` au admin settings.
- Seller entitlement = `totalAmount - platformCommission`.
- Gateway fees (AzamPay) haziko kwenye ledger ya Soko Vibe; zinakatwa na
  provider nje ya mfumo.
- Hakuna payout bila ledger debit inayolingana; hakuna release bila hold.
- Kila operation ya fedha ina idempotency key.

10.2 Order creation na quote

1. Buyer anaunda order kwa product + quantity + address.
2. Order ianzishwa `DRAFT` au `PENDING_SHIPPING_FEE`.
3. Seller anaweka shipping quote (`amount`, `estimatedDays`, `notes`).
4. Quote inaingia `SHIPPING_FEE_SUBMITTED` au `SHIPPING_FEE_REVIEW`.
5. Admin/buyer approval inaiweka `AWAITING_ESCROW_PAYMENT`.
6. `totalAmount` inahesabiwa na kuwa locked kwenye order.

10.3 Payment (AzamPay)

- Buyer anachagua provider (`azampay`, `card`, `bank`); kwa sasa
  `provider-factory` ina `azampay`/`mno_checkout`.
- `POST /orders/:orderId/payments/initiate` inaunda payment record +
  payment attempt + provider checkout.
- Payment status: `pending` -> `processing` -> `paid`/`failed`/`expired`.
- Webhook `POST /api/v1/payments/webhook/azampay`:
  - IP allow-list (`AZAMPAY_ALLOWED_IPS`) + checksum/callback password.
  - Dedupe kwa `dedupKey` kwenye `webhookEvents`.
  - Ina-update payment, order (`ESCROW_HELD`/`IN_ESCROW`), escrow hold na
    notification.
- Webhook outbox (`webhook-outbox.js`) inahakikisha events zinatumwa kwa
  reliability.

10.4 Escrow

- Escrow hold: `{ orderId, paymentId, amount, status: 'holding', ... }`.
- `holding` inashikilia pesa hadi:
  - Buyer anathibitisha delivery (OTP/QR) -> release eligible; au
  - Auto-release baada ya `ESCROW_AUTO_RELEASE_DAYS` (default 14); au
  - Dispute -> hold inabaki hadi resolution.
- Auto-release hairuhusiwi kwa `DISPUTED`; dispute lazima isuluhishwe kwa
  admin.
- Release: escrow -> `released`, order -> `COMPLETED`/`WALLET_CREDITED`,
  wallet ledger `SETTLEMENT_CREDITED`, seller available balance inaongezeka.
- Refund: escrow -> refunded, order -> `REFUNDED`, ledger
  `REFUND_PROCESSED`, buyer refund record.

10.5 Wallet na ledger

Collections: `wallets/{sellerId}` + `walletTransactions/{id}`.
Fields za wallet: `availableBalance`, `pendingBalance`, `frozenBalance`,
`totalEarned`, `totalWithdrawn`, `currency`, `status`.
Ledger types:
- `PAYMENT_RECEIVED` - malipo yamepokelewa (escrow).
- `SHIPPING_FEE_RECEIVED` - shipping.
- `COMMISSION_DEBITED` - commission (0 default).
- `SETTLEMENT_CREDITED` - seller settlement.
- `WITHDRAWAL_DEBITED` - reservation ya withdrawal.
- `WITHDRAWAL_REFUNDED` - payout ilishindikana.
- `REFUND_PROCESSED` - refund kwa buyer.
- `LEGACY_BALANCE`, `ADJUSTMENT` - migration/manual.

Kanuni:
- Balance haipungui chini ya 0.
- Ledger ni append-only; hakuna update/delete.
- Kila entry ina `balanceAfter`, `referenceType`, `referenceId`,
  `idempotencyKey`.

10.6 Withdrawal lifecycle

```
requested -> reserved -> disbursing -> processing -> completed
                                      \-> failed -> (reservation refunded)
```

- `requested`: ombi limeundwa; hakuna pesa iliyohamishwa.
- `reserved`: balance imedebitwa na ledger imeandikwa kwa transaction moja.
- `disbursing`: provider payout call inaweza kuwa inaendelea; retry lazima
  iulize gateway kwanza (`_gatewayHasPayout`).
- `processing`: provider imekubali; inasubiri confirmation pekee.
- `completed`: provider imethibitisha; terminal.
- `failed`: terminal; reservation inarudishwa kwa ledger
  `WITHDRAWAL_REFUNDED`.
- Defaults: `WITHDRAWAL_MIN=0`, `WITHDRAWAL_MAX=5,000,000`,
  `DAILY_WITHDRAWAL_LIMIT=5,000,000`.
- Admin anaweza process/confirm/retry; jobs zinashughulikia stuck withdrawals.

10.7 Refunds

- Refund inaweza kuwa full au partial; inahusiana na order/payment/dispute.
- Status: `pending` -> `processing` -> `completed`/`failed`.
- Refund inaathiri escrow na wallet kwa ledger entry; buyer notification
  inatumwa.
- `refundUnstuck` job inashughulikia refunds zilizokwama.

10.8 Disputes

- Dispute inafunguliwa na buyer (au seller kwa upande mwingine) ikiwa na
  reason, evidence na amount.
- Order inakuwa `DISPUTED`; escrow hold inabaki.
- Admin anaweza:
  - `refund_to_buyer` - refund na order `REFUNDED`.
  - `release_to_seller` - release na order `COMPLETED`.
  - partial/other - kwa manual adjustment.
- SLA: `FINANCE_DISPUTE_SLA_HOURS` (default 72); job inaescalate.
- Dispute evidence iko kwenye `disputeEvidence` na inaweza kuwa na picha,
  maelezo na tracking.

10.9 Reconciliation na commission

- Reconciliation inalinganisha payments, escrow, wallet na provider records;
  inaunda `reconciliations` report.
- Commission default 0; kama imewekwa, inakatwa kwenye settlement na
  kuandikwa `commissionTransactions`.
- Admin settings/config zinaweza kubadilisha commission; mabadiliko
  yanahitaji audit.

10.10 Money invariants (lazima zishike)

1. Order total = product price + shipping fee (kwa order ya kawaida).
2. Escrow hold amount = payment amount = order total iliyolipwa.
3. Seller settlement = order total - commission (commission >= 0).
4. Wallet available balance = sum(ledger entries) kwa wallet hiyo.
5. Withdrawal haiwezi kuzidi available balance.
6. Payout haiwezi kutoka bila `reserved` debit.
7. Refund haiwezi kuzidi amount iliyolipwa.
8. Dispute hold haiwezi auto-release.
9. Kila transition ya order inapita state machine.
10. Kila webhook ina dedupe key; kurudia hakuathiri ledger.

Njia:
A. Email + password

3. Kama MFA imewekwa, `MfaChallengeScreen` inahitaji TOTP kabla ya

B. Phone OTP: send-otp -> verify-otp -> session.
C. Email OTP: send-email-otp -> verify-email-otp -> session.
D. OTP sign-in: `otp-sign-in`.

MFA:
- Enrollment: `/mfa-enrollment` -> QR/manual secret -> code -> recovery codes.

- Credentials mbaya: 401; login limiter (5/15 min).

Edge cases:

- OTP attempts zimezidi: 429/lockout.
- Password mpya ni sawa na ya zamani: policy inakataa.

11.5 App lock, session na logout-all

Edge cases:
- Banned words: moderation inakataa.
- Bei si sahihi/stock 0: validation.
- Media kubwa: presigned upload inakataa size; compression client-side.
- Product imekataliwa: seller anaweza kurekebisha na resubmit.

11.10 Chat, social, follow, groups na status

Chat:
1. Buyer anaanzisha chat kutoka product/seller profile.
2. Conversation inaundwa (`conversations` au `chats`) na participants.
3. Messages: text, picha, sauti, product/order share; read receipts.
4. Push notification inatumwa kwa recipient; in-app badge inasasishwa.
5. Block/report inapatikana; moderation inaweza kuchukua hatua.

Social:
- Follow/unfollow; private account ina follow requests (accept/reject/
  cancel).
- Followers/following lists; suggested accounts.
- Groups: create group, add members, admin roles, group chat.
- Status: `statuses` (24h), views na replies.
- Contact discovery: opt-in, match contacts, privacy.

Edge cases:
- Spam/abuse: rate limits + report.
- Message kwa blocked user: 403.
- Group member removal: admin only.
- Offline: messages queued na kutumwa baadaye.

11.11 Checkout, shipping quote na malipo

1. Buyer anaongeza bidhaa au "Buy now"; `CheckoutScreen` inaonyesha order
   summary.
2. Anwani: `addresses`; buyer anachagua/kuongeza.
3. Order inaundwa `POST /api/v1/orders` (productId, quantity, addressId).
4. Seller anaweka shipping quote `POST /orders/:id/shipping-quote`
   (amount, estimatedDays, notes).
5. Buyer/admin anaapprove `POST /orders/:id/shipping-quote/approve`;
   `totalAmount = productPrice + shippingFee`.
6. Buyer anachagua malipo: AzamPay (M-Pesa/Tigo/Airtel/Halopesa/card/bank).
7. `POST /orders/:id/payments/initiate` inaunda payment + attempt na
   inatuma USSD push/checkout URL.
8. Buyer anathibitisha kwenye simu; UI inaonyesha "processing" na poll
   ya status.
9. Webhook inathibitisha malipo; order inakuwa `PAID`/`ESCROW_HELD`.
10. Buyer na seller wanapata notification; seller anaona "ready to dispatch".

Edge cases:
- Malipo yamekataliwa: order inarudi `AWAITING_ESCROW_PAYMENT`/`FAILED`;
  buyer anaweza kujaribu tena.
- Timeout: payment inaisha (`expireStalePayments`) na order inaweza
  kughairiwa.
- Quote imebadilika: buyer anahitaji approval mpya.
- Shipping fee 0: seller anachukua gharama (inaruhusiwa).
- Double click: idempotency inazuia order/payment mara mbili.

11.12 AzamPay webhook na escrow hold

1. AzamPay inatuma `POST /api/v1/payments/webhook/azampay`.
2. Server inakagua:
   - IP iko kwenye `AZAMPAY_ALLOWED_IPS` (kama imewekwa),
   - callback password/checksum (`AZAMPAY_CALLBACK_PASSWORD`,
     `AZAMPAY_CHECKSUM_KEY`),
   - JSON shape na reference.
3. `webhookEvents` dedupe kwa `dedupKey`; duplicate inarudisha 200 bila
   kuathiri ledger.
4. Payment inasasishwa (`paid`/`failed`), payment attempt, order status.
5. Escrow hold inaundwa/updated: `status='holding'`, amount, paymentId,
   `autoReleaseAt` (siku 14 default).
6. Ledger entries: `PAYMENT_RECEIVED`, `SHIPPING_FEE_RECEIVED` (kama
   applicable); commission 0.
7. Notification kwa buyer/seller; receipt inaundwa.
8. Outbox inahakikisha events za ndani zinatumwa kwa reliability.

Edge cases:
- Webhook imechelewa baada ya order kughairiwa: refund/manual review.
- Webhook duplicate: dedupe.
- Amount mismatch: order inawekwa review; hakuna release.
- Provider down: retry/outbox; finance job inarekebisha.

11.13 Dispatch, delivery na OTP/QR handover

1. Seller anaona order `ESCROW_HELD`/`SELLER_ACCEPTED`.
2. `SellerDispatchScreen`: courier name + tracking number ->
   `POST /orders/:id/dispatch`.
3. Order inakuwa `DISPATCHED`/`IN_TRANSIT`; buyer notification.
4. Delivery: courier/buyer inaweza kuweka `OUT_FOR_DELIVERY`, `ARRIVED`,
   `DELIVERED`.
5. Handover:
   - `POST /api/v1/handover/:orderId/otp/issue` inatengeneza OTP (hash,
     TTL, attempts) na kumtumia buyer.
   - Buyer anampa courier/seller OTP; `POST /:orderId/otp/verify`.
   - Au QR: `POST /:orderId/qr/verify`.
6. Baada ya verification: `DELIVERY_CONFIRMED`; escrow inakuwa tayari
   release; inspection period inaweza kuanza.
7. Buyer `POST /orders/:id/complete` au auto-release.

Edge cases:
- OTP imeisha/attempts zimezidi: issue mpya kwa rate limit.
- OTP imeshirikiwa vibaya: seller/courier anaweza kuripoti; dispute.
- Delivery imeshindikana: `DELIVERY_ATTEMPTED`; reschedule au refund.
- Buyer hayupo: courier anaripoti; order inabaki hold.

11.14 Auto-release na settlement

1. Finance job `finance.inspectionAutoRelease` kila saa inatafuta orders
   zilizo `DELIVERED`/`INSPECTION_PERIOD` na `autoReleaseAt <= now`.
2. Dispute ikiwa `DISPUTED`, hairuhusiwi auto-release.
3. Release:
   - escrow hold -> `released`,
   - order -> `COMPLETED`/`WALLET_CREDITED`,
   - wallet ledger `SETTLEMENT_CREDITED`,
   - seller available balance += total - commission,
   - buyer/seller notifications,
   - receipt/audit.
4. Idempotency: release key inazuia mara mbili.
5. Settlement inaonekana kwenye seller earnings/ledger.

Edge cases:
- Seller hajafanya dispatch: hakuna auto-release.
- Buyer hajathibitisha: auto-release baada ya siku 14 (default).
- Dispute baada ya release: admin manual resolution/refund.

11.15 Wallet na withdrawal

1. Seller anaona `wallet` (available/pending/frozen) kwenye
   `SellerEarningsScreen`.
2. `POST /api/v1/wallet/withdrawals` na amount + payout phone.
3. Server:
   - `requested` -> unda withdrawal,
   - `reserved` -> debit available + ledger `WITHDRAWAL_DEBITED`
     (transaction moja),
   - `disbursing` -> provider payout call,
   - `processing` -> provider accepted,
   - `completed` -> confirmed; au `failed` -> refund reservation.
4. Admin anaweza process/confirm/retry; job inashughulikia stuck.
5. Seller anaona status na receipt.

Edge cases:
- Amount < min / > max / > balance: 400/409.
- Wallet frozen: 409 `WALLET_FROZEN`.
- Provider timeout: `disbursing` inabaki; job inauliza gateway kwanza.
- Duplicate request: idempotency.
- Payout phone si sahihi: validation; failed -> refund.

11.16 Refund

1. Buyer anaomba refund (order detail/dispute).
2. `POST /api/v1/refunds` inaunda refund `pending` na correlationId.
3. Admin ana-review; `PUT /api/v1/refunds/:refundId/process`.
4. Refund inatekelezwa kwa provider (AzamPay) au manual; status
   `processing` -> `completed`/`failed`.
5. Escrow: hold inarelease kwa buyer; order `REFUNDED`; ledger
   `REFUND_PROCESSED`.
6. Buyer notification + receipt.

Edge cases:
- Order tayari completed: refund inaweza kuhitaji manual.
- Partial refund: amount < total; ledger inaheshimu.
- Refund imekwama: `refundUnstuck` job.
- Refund baada ya withdrawal: balance inaweza kuwa negative; admin
  adjustment.

11.17 Dispute

1. Buyer/seller ana fungua dispute `POST /api/v1/disputes` au
   `/orders/:id/dispute`.
2. Order -> `DISPUTED`; escrow hold inabaki.
3. Evidence: `POST /disputes/:id/evidence` (picha, maelezo, tracking).
4. Admin anaona queue; `PUT /disputes/:id/resolve`:
   - `refund_to_buyer`, `release_to_seller`, au partial.
5. Resolution inaathiri escrow/wallet/order; notifications.
6. SLA: 72h default; `escalateDisputes` job.

Edge cases:
- Dispute baada ya auto-release: admin manual.
- Evidence kubwa: upload limits.
- Seller haijibu: admin anaweza kutoa default kwa buyer.
- Repeated disputes: trust score inashuka.

11.18 Cancel na expire

Cancel:
1. Buyer/seller/admin ana-cancel kwa conditions (order haijadispatch).
2. Order -> `CANCELLED`; escrow -> refund buyer kama imelipwa.
3. Notifications na ledger.

Expire:
1. `finance.paymentExpire` inatafuta payments `pending` zaidi ya
   `FINANCE_PAYMENT_EXPIRE_MS` (default 24h).
2. Payment -> `expired`; order -> `EXPIRED`/`CANCELLED`.
3. Stock inareleased; buyer notification.

Edge cases:
- Cancel baada ya dispatch: hairuhusiwi; dispute/refund.
- Expire wakati webhook inakuja: dedupe/status guard.
- Order iliyolipwa: cancel inahitaji refund.

11.19 Reviews, comments na ratings

12.1 Topology

```
Flutter app (Android/iOS/Web/Desktop)
   |
   | HTTPS + Firebase ID token
   v
Cloudflare Edge Worker "soko-api-edge"   (api.sokovibe.co.tz)
   |  cache hot reads, block scanners, body cap, headers
   v
Render Web Service "soko-langu-api"      (Express, Firestore facade)
   |            |               |
   |            |               +--> Cloudflare R2 (media/KYC/backups)
   |            +------------------> Redis (rate limits, OTP, queues, cache)
   +-------------------------------> Firebase Firestore + Auth
   |
Render Worker "soko-langu-worker" (finance/media queues)
   |
Cloudflare Worker "soko-ai-edge" (Workers AI, server-to-server)
   |
Cloudflare Worker "soko-media" (media.sokovibe.co.tz -> R2 buckets)
```

Sehemu nyingine:
- Firebase Hosting: site `sokonimoko-8c171-a8d14` (landing/assets).
- Static admin panel: `/admin` kwenye Express + `admin.sokovibe.co.tz`.
- Landing: `server/landing` (inazalishwa kutoka `web_landing`).
- Firestore rules/indexes zinasambazwa kwa Firebase CLI.

12.2 Edge cache worker (`cf-worker/`)

Worker: `soko-api-edge`; route `api.sokovibe.co.tz/*`; origin
`https://soko-langu-server.onrender.com` (inaweza kubadilishwa kwa
`ORIGIN_URL`).

Routes zinazocache:
| Route | TTL | Key |
|---|---|---|
| `GET /api/trust/passport/:sellerId` | 300s | path |
| `GET /api/transaction-status/:orderId` | 15s | path + token |
| `POST /api/search/global-search` | 60s | path + body |
| `POST /api/search/autocomplete` | 90s | path + body |
| `POST /api/search/trending` | 300s | path + body |
| `POST /api/search/most-rated` | 600s | path + body |

Tabia:
- Stale-while-revalidate: entry iliyoisha inatumwa instant na refresh
  inaendelea background.
- Header `x-edge-cache`: `MISS`, `HIT`, `STALE`, `MISS-ORIGIN-ERROR`,
  `MISS-NOKEY`; pia `x-soko-edge: 1`.
- Cache key ni GET request yenye URL-encoded path (Cache API haikubali POST
  key); body inahashwa.
- Non-200 haicache (haiti poison 429/500).
- Mutations, admin, payments, escrow, auth hazicache kamwe.

Edge protections:
- Scanner/probe blocking: `/.env`, `/.git/*`, `/wp-*`, `*.php`,
  `/phpmyadmin`, `/server-status`, `/actuator`, `/.aws` -> 404.
- Body cap: non-GET/HEAD > 1MB -> 413.
- Origin timeout: 25s (origin 20s).
- Security headers: HSTS, nosniff, referrer-policy, permissions-policy;
  huondoa `x-powered-by`/`server`.
- Optional KV rate brake: `RATE_LIMIT_KV`, 120 req/min/IP kwa uncached
  traffic (eventually consistent; origin limiter ndiyo source of truth).
- `EDGE_SECRET`: worker inatuma `x-soko-edge`; origin inatumia
  `cf-connecting-ip` kwa rate limit only kama secret inalingana.

12.3 Origin (Render)

`server/render.yaml`:
- `soko-langu-api`: web, rootDir `server`, `npm ci`, start

- `server/Dockerfile`: `node:20-slim`, `npm ci --omit=dev --no-optional`,

- `docker-compose.yml` bado ina postgres kwa legacy dev; runtime haitumii.

Uwazi: render.yaml bado inataja ClickPesa kwenye comments; code ya sasa ni

13. SECURITY NA COMPLIANCE
================================================================================

13.1 Authentication na authorization

- Firebase Auth ndiyo identity provider; server inathibitisha ID token kwa
  kila request.
- `users/{uid}` ina role/status; `requireActive` inazuia suspended.
- Admin: `x-admin-secret` + `x-admin-totp`; admin ya KYC ina database role
  check; staff login na MFA.
- RBAC: buyer, seller, admin, super_admin, staff; company RBAC ipo kwenye
  module (haijamountiwa).
- Sessions: `sessionRevokedAt`, logout-all, device tokens.
- MFA: TOTP enrollment/challenge/recovery codes; admin/staff.
- App Check: Firebase App Check kwa endpoints za nyeti.

13.2 Transport na headers

- HTTPS everywhere; HSTS 1 year includeSubDomains.
- CSP: default-src self; script/style/img/connect/font/frame allow-lists
  kwa Firebase/Google/Tailwind/jsDelivr/unpkg/Turnstile.
- `X-Frame-Options: DENY`, `nosniff`, `X-XSS-Protection`,
  `Referrer-Policy`, `Permissions-Policy` (camera/mic/geo off).
- CORS allow-list; credentials false.
- `x-powered-by` imezimwa.
- Edge inaondoa fingerprint headers.

13.3 Input, validation na abuse prevention

- Zod validation kwa body/query/params; 400 yenye details.
- Body limit 1MB; URI limit 8KB; timeout 20s.
- Rate limits per IP/user/route (Section 7.5).
- Load shedder 503 kwa overload.
- Scanner blocking edge.
- Moderation: profanity filter, report/moderation queue, text check.
- Turnstile kwa public forms.
- File uploads: presigned, size/type checks, no executable content.

13.4 Payment security

- Amount haitoki kwa client; server inahesabu kutoka order/product.
- AzamPay webhook: IP allow-list, callback password/checksum, dedupe.
- Idempotency keys kwa payment, webhook, ledger, withdrawal.
- Escrow hold/release state machine; hakuna release bila hold.
- Withdrawal: atomic reserve + ledger; payout inaanza tu kutoka `reserved`;
  `disbursing` retry inauliza gateway kwanza.
- Reconciliation ya kila siku/saa.
- Admin actions zina audit log.
- Provider secrets haziko kwenye client.

13.5 Wallet na fraud

- Balance inahesabiwa kutoka ledger; client haiwezi kuandika balance.
- `fraud_prevention_service.dart` (client) + server fraud checks.
- Daily sale limit `MAX_DAILY_SALE_AMOUNT` (default 5,000,000 TZS).
- Withdrawal limits: max 5,000,000; daily 5,000,000; min 0.
- Account suspension/ban; admin review.
- Duplicate KYC detection; device/session risk.

13.6 Media na KYC privacy

- KYC bucket haijabound kwa media worker; hakuna public URL.
- Read-url ya muda mfupi tu; admin role/secret inahitajika.
- Product media ni public; KYC/user documents ni private.
- Signed URLs hazihifadhiwi kwenye logs.
- PII helpers (`utils/pii.js`) kwa masking.

13.7 Secrets na config

- Secrets kwenye Render/Cloudflare/Firebase dashboards; `.env.production`
  haipaswi kucommit.
- `.env.example` ina majina ya variables.
- `CREDENTIALS.txt` ipo kwenye repo root - **hatari**; inapaswa kuondolewa
  na ku-rotate secrets (Section 16).
- Production inakataa kuanza bila `APP_URL`,
  `AZAMPAY_COLLECTION_WEBHOOK_URL`, `AZAMPAY_CALLBACK_PASSWORD`.

13.8 Logging, audit na privacy

- Structured JSON logs zenye requestId; hakuna secrets/body.
- `auditLogs`/`audit_log` kwa admin na finance actions.
- `consentRecords` kwa terms/privacy/marketing.
- Data export/deletion workflows.
- Password hashing: Firebase Auth; local PIN/biometric secure storage.
- Client: root/jailbreak/emulator detection, app lock, secure storage.

13.9 Compliance (Tanzania context)

- Data protection: consent, purpose limitation, deletion/export.
- KYC/AML: identity verification, record keeping, audit.
- Consumer protection: escrow, refunds, disputes, terms/privacy.
- Payment regulations: AzamPay licensed provider; platform haishikilii
  funds directly.
- Tax/receipts: receipts na audit records.

18. GLOSSARY
================================================================================

- **Escrow** - pesa ya mnunuzi inashikiliwa na mfumo hadi delivery
  ithibitishwe; inalinda pande zote.
- **Hold** - escrow record inayoshikilia kiasi (`status=holding`).
- **Release** - kutoa escrow kwa seller baada ya delivery/auto-release.
- **Settlement** - kuweka pesa kwenye wallet ya seller.
- **Auto-release** - release ya escrow baada ya siku 14 (default) bila
  dispute.
- **Dispute** - mgogoro rasmi unaozuia release hadi admin aamue.
- **Refund** - kurudisha pesa kwa buyer.
- **Chargeback** - malipo yanayorudishwa na provider/bank (haijatekelezwa
  kikamilifu).
- **KYC** - Know Your Customer; uthibitisho wa utambulisho.
- **Blue Tick** - badge ya seller aliyethibitishwa.
- **Trust passport** - muhtasari wa trust score/reliability wa seller.
- **Commission** - fee ya jukwaa; default 0.
- **Wallet** - balance ya seller ndani ya mfumo.
- **Ledger** - kumbukumbu ya kila movement ya pesa.
- **Withdrawal** - kutoa pesa kutoka wallet kwenda mobile money/bank.
- **Payout** - malipo ya withdrawal kupitia provider.
- **Idempotency** - operesheni ile ile kurudiwa haiathiri mara mbili.
- **Webhook** - callback ya provider kwa mfumo.
- **Dedupe** - kuzuia webhook/event kushughulikiwa mara mbili.
- **Reconciliation** - kulinganisha records za mfumo na provider.
- **OTP** - namba ya siri ya mara moja.
- **TOTP** - OTP ya muda (MFA app).
- **MFA** - uthibitisho wa hatua mbili.
- **Session revocation** - kufuta sessions zote.
- **App Check** - uthibitisho wa app halisi kwa Firebase.
- **Store Facade** - layer inayoficha Firestore nyuma ya API ya models.
- **Edge cache** - cache ya Cloudflare karibu na mtumiaji.
- **R2** - object storage ya Cloudflare.
- **Presigned URL** - URL ya muda ya upload/download.
- **Feed ranking** - mpangilio wa bidhaa kwenye home.
- **Boost** - matangazo ya bidhaa kwa muda.
- **Flash sale** - bei ya muda mfupi.
- **Buyer request** - ombi la bidhaa kutoka kwa mnunuzi.
- **Referral** - mwaliko wa mtumiaji mpya.
- **Trial** - kipindi cha bure cha subscription.
- **Entitlement** - haki/features za plan.
- **SLA** - muda wa kuhudumia (mfano disputes 72h).
- **Load shedding** - kukataa requests kwa 503 wakati overload.
- **Circuit breaker** - kuzuia provider mbovu kwa muda.
- **Idempotency key** - key ya kuzuia duplicate.
- **BigInt** - integer kubwa kwa pesa.
- **TZS** - Tanzania Shilling.
- **MNO** - Mobile Network Operator (M-Pesa, Tigo, Airtel, Halopesa).
