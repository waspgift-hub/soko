1. ARCHITECTURE OVERVIEW
================================================================================
- Frontend: Flutter app (lib/). Talks to Firebase (Auth, Firestore, Storage,
  Functions, Crashlytics, Perf, App Check) AND a Node/Express REST API.
- Backend: Single Node.js Express server (server/index.js, ~8,405 lines) running
  on Render at https://soko-langu-server.onrender.com.
- A standalone listener process (server/listener.js) handles Firestore-triggered
  notifications + SMS. It is NOT required by index.js.
- The old Firebase Functions directory (functions/) is DEPRECATED (reference only).
  All webhooks + notification listeners now run on the Render Express server.
- Payment provider: ClickPesa (Tanzania) - USSD Push, BillPay, Payouts.
- Push notifications: OneSignal. SMS: Meseji (primary) + Notify Africa (fallback).
- AI: Groq (chat + Whisper transcription).
- Database: Firestore (NoSQL). Local cache: Hive + SharedPreferences + sqflite.

Backend base URL is in lib/services/api_config.dart:
    https://soko-langu-server.onrender.com

4. AUTHENTICATION FLOW
================================================================================
Files: lib/screens/auth/*, lib/services/auth_service.dart,
       lib/repositories/auth_repository.dart, lib/services/account_manager.dart

Methods supported:
  A) Phone OTP login
     1. User enters phone number -> POST /api/auth/send-otp
        (server hashes 6-digit OTP, stores in otp_codes/{phone}, 10-min expiry,
         max 3 sends per 15 min, rate-limited)
     2. User receives SMS -> enters code -> POST /api/auth/verify-otp
     3. If phone not registered: POST /api/phone-login auto-creates a user:
        email = phone_{clean}@soko-vibe.com, default doc with
        coins=0, viewerCoins=0, sellerBalance=0, soldCount=0,
        isAdmin=false, isSuspended=false
     4. Server returns Firebase custom token -> app signs in.
  B) Email/Password register & login (lib/screens/auth/login_screen.dart,
     register_screen.dart). Saved account stored locally (SavedAccount).
  C) Google sign-in (google_sign_in + Firebase Auth).
  D) Magic link login (lib/services/magic_link_service.dart).
  E) Forgot password: reset by phone or email (server reset-password-by-phone
     requires 8+ chars, uses firebase auth updateUser).

On successful login:
  - AccountManager saves account locally (uid, email, displayName, photoUrl).
  - AuthNotifier updates state -> AuthGate routes to MainWindow.
  - AnalyticsService starts session heartbeat.

Login via OTP screen: lib/screens/auth/otp_screen.dart
Profile setup after first auth: lib/screens/auth/profile_setup_screen.dart
  (collects full name, profile picture upload -> Firestore users doc)

Security:
  - lib/services/security_service.dart (app lock).
  - lib/widgets/app_lock_overlay.dart (biometric/PIN overlay).
  - lib/services/fraud_prevention_service.dart (risk scoring).

12. ORDERS FLOW (BUYER)
================================================================================
Files: lib/screens/orders/my_purchases_screen.dart, lib/screens/buyer/*,
       lib/models/payment_model.dart, lib/models/transaction_model.dart
Order lifecycle statuses:
  pending -> quoted -> paid -> escrow_hold -> dispatched -> confirmed -> completed
  cancelled / refunded / disputed / failed

Steps:
1. Buyer adds item to cart / clicks Buy Now -> checkout screen (/checkout).
2. Create order: POST /api/orders/create
   (orderEngine.createOrder -> status pending; mirrors transaction status
    "awaiting_shipping_quote" so payment is hidden until seller quotes).
3. Seller quotes shipping (see section 13). Status -> quoted.
4. Buyer pays (see section 14) -> escrow_hold.
5. Buyer fills transport details (buyer_transport_sheet / buyer-transport):
   bus/bodaboda/pikipiki details while escrow_hold; notifies seller.
6. Seller dispatches (escrow/dispatch) -> dispatched.
7. Buyer confirms receipt (escrow/release) -> delivered + completed;
   funds released to seller.
- My purchases (/my-purchases): list of buyer orders with status + timeline
  (orderTimeline collection), order detail (/order-detail), order flow
  (/order-flow), receipt PDF (/receipt) via lib/services/receipt_pdf_service.dart.
- Payment result dialog: lib/widgets/payment_result_dialog.dart.
- Transaction status watcher: lib/widgets/transaction_status_watcher.dart
  (polls GET /api/transaction-status/:orderId).

14. PAYMENTS & ESCROW FLOW (CLICKPESA)
================================================================================
Files: lib/services/payment_service.dart, lib/services/clickpesa_service.dart,
       server/clickpesa.js (ClickPesa client), server/index.js (webhook/payment)
Payment methods:
  - USSD Push (collect): buyer gets USSD prompt. Tiered fees (TZS 54..7,960).
  - BillPay: generates control number; 1% gateway fee (2% HaloPesa, 1% CRDB)
    added on top via calcGatewayFee(methodId, amount, provider).
  - Wallet balance deduction.

Purchase flow (escrow):
1. POST /api/create-marketplace-payment-link
   - Verifies Firebase token; fraud checks (suspended, duplicate pending,
     daily limit).
   - resolveEffectivePrice(): if an active flash sale exists for the product,
     the client-supplied full price is overridden with salePrice, so commission
     and total are always computed on the real discounted price.
   - totalAmount = price + shipping + 3.5% commission + gateway fee.
   - tx id = p{base36}{first4alphanum of buyerId}.
   - BillPay -> control number. USSD -> async ClickPesa Collect (ussdSent flag).
2. Buyer completes payment on phone.
3. ClickPesa webhook -> POST /api/clickpesa/webhook (verifyWebhook via
   WEBHOOK_SECRET; always returns 200 {received:true}).
4. applyClickPesaPayment():
   - deposit: credits users.walletBalance.
   - boost: marks tx completed, sets product isBoosted/boostedUntil/isFeatured.
   - purchase: status escrow_hold; sellerReceives = price + shipping;
     mirrors orders doc; records commission revenue; decrements flash-sale
     stock; increments seller pendingEscrow/totalSales/grossSalesVolume.
   - Guards: completed/escrow_hold skip double-processing.
5. Release (buyer confirm): escrow/release -> checks suspended seller (funds
   held), delivered + escrowReleased, pendingEscrow -> sellerBalance
   (safe decrement), revenue_transactions + auditLog. Auto-payout if enabled.
6. Admin force release: /api/escrow/admin-release (x-admin-secret).
7. Cancel (buyer, pre-dispatch): /api/escrow/cancel -> ClickPesa refund
   (price+shipping-2000 fee), refunded status.
8. Dispute: /api/escrow/dispute (funds stay held, alerts admins);
   admin-resolve-dispute (release or refund).
9. Auto-release: cron /api/cron/release-escrows
   (escrow_hold/dispatched + expired -> delivered + sellerBalance credit).
   ESCROW_AUTO_RELEASE_DAYS is a single global override (default 0 = unset).
   When set it applies to BOTH local and regional escrows; otherwise local
   auto-release = 3 days, regional = 7 days (ESCROW_LOCAL_DAYS/REGIONAL_DAYS).

Retry payment: POST /api/retry-payment (>=30s old, buyer/admin only).

ClickPesa webhook status mapping:
  completed/payment_received/payment_completed/success/settled -> success
  failed/cancelled/expired -> failed

15. WALLET FLOW
================================================================================
Files: lib/services/* (balance_privacy_service), server routes
- Deposit: POST /api/wallet/deposit (USSD or BillPay, depositRef=dep+base36).
- Purchase from balance: POST /api/wallet/purchase (balance deduction ->
  escrow_hold; mirrors tx on existing orderId). Server-side money math:
  commission is always PLATFORM_COMMISSION_PERCENT (never trusted from a
  client-supplied serviceFeePercent), prices go through resolveEffectivePrice()
  for flash sales, and the deducted amount is recomputed server-side as
  committedTotal = price + shipping + commission.
- Balance: GET /api/wallet/balance/:userId.
- History: GET /api/wallet/history/:userId; DELETE /api/wallet/delete-history.
- Payment methods: GET /api/payment-methods, POST /api/payment-methods/calc-fee,
  GET /api/wallet/deposit/methods, POST /api/gateway-fee.
- Buyer statement: GET /api/buyer-statement (debits for PAID_STATUSES,
  credits for refunds + deposits).

16. WITHDRAWAL / PAYOUT FLOW
================================================================================
- Seller balance: GET /api/seller/balance.
- Withdraw: POST /api/seller/withdraw
  - Firestore runTransaction atomic deduct (amount + payout fee tier).
  - ClickPesa payout; reversal on failure; audit + notify.
  - MIN_WITHDRAWAL = 5000. DEFAULT_PAYOUT_FEE = 2000 (estimate).

  FAILED -> atomically reverse deducted amount back to seller wallet).

17. BOOST FLOW
================================================================================
Files: lib/services/boost_service.dart, lib/models/boost_tier.dart,
       lib/models/boost_receipt.dart, lib/widgets/boost_promo_banner.dart,
       lib/screens/boost/product_boost_screen.dart, /boost-receipt
Boost tiers (server): bronze TZS1500/3d, silver TZS3000/7d, gold TZS10000/30d.
Flow:
1. Seller selects tier -> POST /api/boost-product
   - verifies token; cancels stale pending boosts; normalizes phone to 255.
   - BillPay adds 1% gateway fee; USSD sends tier price.
   - writes transactions doc (type boost, status pending); fires ClickPesa.
   - USSD failure -> failed + notifyBoostPaymentFailed (in-app + push + SMS).
2. ClickPesa webhook -> applyClickPesaPayment boost branch:
   tx completed, product isBoosted/boostedUntil/isFeatured, schedules broadcast.
3. Boost notify: POST /api/boost/notify paginates users (500/batch),
   OneSignal bulk + in-app notifications.
4. Stale boosts fail: failStalePendingBoosts (cron).
Boost analytics: boost_analytics/{pid}/impressions.

18. FLASH SALES FLOW
================================================================================
Files: lib/services/flash_sale_service.dart, lib/models/flash_sale_model.dart,
       lib/widgets/flash_sale_banner.dart, lib/screens/flash_sale (create/screen)
- FlashSale model: discountPercent (e.g. 30%), startTime/endTime, isActive,
  stock, soldCount, productId, sellerId.

  matching product-detail behavior).

- Notify: 24h OneSignal cooldown via app_settings/flash_sale_push_cooldown.
- Deactivate expired: POST /api/flash-sales/deactivate-expired.
- Flash sale screen: /flash-sale (banner + active deals).
- Product cards + banner show flash sale price/discount.
- Money enforcement: server helper resolveEffectivePrice(db, productId,
  clientPrice) reads the active flash sale (isActive + endTime in future) and
  overrides the client-supplied price with salePrice on order creation,
  payment-link, wallet purchase, and legacy transaction create. This means a
  buyer is never charged the stale full price and the 3.5% commission is
  always computed on the real sale price.

27. SEARCH ENGINE (BACKEND DETAIL) - server/search.js (487 lines)
================================================================================
Collections: search_index_products, search_index_users, search_index_categories,
             search_analytics, search_trending.
- Trigram index: extractTrigrams (3-char n-grams, lowercase).
- Keywords: extractKeywords (words >= 2 chars).
- Fuzzy correction: levenshtein + fuzzyCorrect (min length 3).
- Relevance score:
    name exact           100
    name startsWith       80
    name includes         60
    description includes  50
    keywords any-word     40 + 5 x hitCount
    trigram ratio        x30
    popularity           x0.1
    isBoosted           +50
    isActive false      -100
    kycApproved         +20
    stock <= 0          -50   (floored at 0)
- Distance-aware sorting (haversine, R=6371 km).
- Routes: POST /global-search (auth, pagination, filters minPrice/maxPrice/
  category/condition/verifiedOnly/nearby), /autocomplete (90s TTL),
  /trending (5-min TTL), /record-click (viewCount++), /most-rated
  (top by reviewCount + aggregated seller ratings, 10-min TTL).
- Cache: cache.js in-memory TTL Map (500 max, lazy prune).

  flash_sales/{id}, buyer_requests/{id}
  reports, groups, status/{id}, app_settings (flash_sale_push_cooldown)
  wishlist (users/{uid}/wishlist or top-level)

firestore.rules highlights:
  - isSignedIn, isOwner, isAdmin (email in {admin@soko-langu.com,
    admin@soko-vibe.com} OR users.isAdmin == true), notSuspended.
  - users: read signed-in; create isOwner; update/delete isOwner||isAdmin.
  - following/followers/admin_withdrawals/cart: owner read+write.
  - products: read public; writes restricted.
  - reviews: create requires sellerId != request.auth.uid (blocks self-rating);
    update: author can only update likedBy/helpfulCount; seller can only update
    sellerReply/sellerReplyAt.

firestore.indexes.json (composite indexes):
  conversations (participants CONTAINS + lastMessageTime DESC)
  transactions (buyerId+createdAt DESC, sellerId+createdAt DESC,
                sellerId+status ASC)
  flash_sales (isActive+endTime ASC, sellerId+endTime ASC,
               productId+isActive ASC, productId+isActive+endTime ASC)
  notifications (userId+isRead ASC)
