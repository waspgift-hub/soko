4. MFUMO WA MALIPO NA ESCROW (PAYMENT & ESCROW)
================================================================================

  Gateways: ClickPesa (halisi) — NOT Mongike. Mongike ni plugin ya zamani ya
  WooCommerce (mongike-payment-gateway/) na webhook ya legacy /api/webhook.

4.1 Njia za Malipo (Payment Methods)
------------------------------------------------
  - wallet        (pochi ya ndani)
  - ussd_push     (ClickPesa USSD push - anayeuziwa anapokea USSD)
  - billpay       (ClickPesa BillPay - order control number)
  - HaloPesa BillPay (2%), CRDB BillPay (1%), CRDB Direct Debit (flat 2,000) -
    provider inatumwa kwenye calcGatewayFee(methodId, amount, provider)

4.2 Kadi za Ada (Fee Tables) — clickpesa.js + transaction_model.dart
------------------------------------------------
  - Soko Vibe Commission: 3.5% ya bei ya bidhaa (salePrice kwa flash sale)
    (PLATFORM_COMMISSION_PERCENT = 0.035, index.js:698)
  - ClickPesa USSD Push fee: tiers 54–7,960 TZS kutegemea kiasi
    (frontend ussdPushFeeTiers: 500-3,000,000; max 7,960)
  - Payout fee: TZS 2,000 (muuzaji analipa anapotoa pesa)
  - Kiwango cha juu cha mauzo kwa siku: TZS 5,000,000 (MAX_DAILY_SALE_AMOUNT)

  Hesabu ya Checkout (TransactionFeeBreakdown):
    processingFee = getUssdPushFee(productPrice)
    platformFee   = productPrice * 3.5%
    totalAmount   = productPrice + platformFee + processingFee
    sellerReceives= productPrice  (muuzaji anapata bei kamili baada ya escrow)

4.3 Ununuzi kupitia ClickPesa USSD (Create Payment Link)
------------------------------------------------
  1. Mnumuzi anabofya Buy Now kwenye product_detail / checkout_screen
  2. Checkout: anachagua deliveryType local/regional + phone
  3. App inaitwa POST /api/create-marketplace-payment-link
     (clickpesa_service.initiateMarketplacePayment)
  4. Server inathibitisha:
     - Mnumuzi si suspended (checkSuspended)
     - Hakuna duplicate payment (transaction inasubiri)
     - Daily limit haijafikiwa (TZS 5M/siku)
     - Rate limit (paymentRateLimit)
  5. Server inaita ClickPesa initiate-ussd-push-request
  6. ClickPesa inasukuma USSD -> mnumuzi anaingiza PIN
  7. ClickPesa inatuma webhook POST /api/clickpesa/webhook (HMAC verifyWebhook)
  8. Server inasasisha transaction: status -> escrow_hold
     - platformFee (3.5%) -> platform
     - pendingEscrow ya muuzaji += sellerReceives (bei + shipping)
     - totalSales++, grossSalesVolume += bei
     - revenue_transactions type 'sale'
     - Arifa kwa mnunuzi + muuzaji (OneSignal + in-app + SMS)

4.4 Escrow Lifecycle
------------------------------------------------
  Hali za transaction: pending -> awaiting_payment -> quoted -> escrow_hold
  -> dispatched -> delivered/completed/disputed/cancelled/failed/refunded

  - escrow_hold : pesa zimeingia lakini bado hazijatolewa kwa muuzaji
  - dispatch    : POST /api/escrow/dispatch  (muuzaji anatuma uthibitisho:
                  trackingNumber, receiptUrl, photoUrl, note)
  - release     : POST /api/escrow/release   (mnunuzi anathibitisha kupokea)
                  -> sellerBalance += sellerReceives; revenue record
  - cancel      : POST /api/escrow/cancel    (kabla ya dispatch -> refund kamili;
                  baada ya dispatch -> inahitaji admin)
  - dispute     : POST /api/escrow/dispute   (sababu + ushahidi) -> disputed
  - admin-release / admin-resolve-dispute   (release au refund)

  Auto-release (cron ya saa 1): transaction iliyo escrow_hold/dispatched
  yenye escrowExpiresAt <= sasa inabadilishwa kuwa delivered na pesa zinatolewa.
    - local   : siku 3  (ESCROW_LOCAL_DAYS = 3)
    - regional: siku 7  (ESCROW_REGIONAL_DAYS = 7)
    - (env: ESCROW_AUTO_RELEASE_DAYS ni global override — ikiwa imewekwa (>0)
      inatumika kwa local NA regional; default 0 = habadili tabia ya 3/7)

4.5 Utoaji wa Pesa (Withdrawals & Payouts)
------------------------------------------------
  - POST /api/seller/withdraw: anaondoa amount + TZS 2,000 (payout fee)
    kwenye sellerBalance; inaunda payout (po_ ref, hali
    pending/processing/success/failed/refunded/reversed); inaita
    clickpesaPayout() kinyuma (fire-and-forget)
  - POST /api/create-payout (admin): payout ya mwongozo + preview
  - POST /api/payout/retry/:id: majaribio hadi PAYOUT_RETRY_MAX=3
  - POST /api/clickpesa/payout-webhook (HMAC):
      SUCCESS -> payout completed
      FAILED  -> kiasi kinarejeshwa kwenye sellerBalance (atomic reverse)
  - POST /api/admin/withdraw: mapato ya matangazo + commission -> simu ya admin
  - Kiwango cha chini cha uondoaji: TZS 5,000

4.6 Webhooks (zote zinathibitisha x-webhook-secret / HMAC)
------------------------------------------------
  - POST /api/clickpesa/webhook         (malipo ya bidhaa/boost)
  - POST /api/clickpesa/payout-webhook  (hali ya payout)
  - POST /api/webhook                   (LEGACY Mongike-style, bado inatumika
                                          kwa malipo ya boost)

5. ORDER ENGINE (MFUMO MPYA WA ORDERS) — server/orders.js
================================================================================

  Hii ni state machine tofauti (orders/{orderId}) inayopangwa kwa ajili ya
  mauzo ya "shipping quote" (muuzaji anatoa bei ya usafirishaji kwanza).

  Hali za ORDER:
    pending -> quoted -> paid -> escrow_hold -> dispatched -> confirmed
    -> completed | cancelled | disputed -> refunded | failed

  Hali za ESCROW_STATUS: held, released, disputed

  Uhamisho halali (isValidTransition):
    pending    -> quoted | cancelled
    quoted     -> paid   | cancelled
    paid       -> escrow_hold | failed
    escrow_hold-> dispatched | disputed | cancelled
    dispatched -> confirmed | disputed
    confirmed  -> completed | disputed
    disputed   -> refunded | completed

  Michakato:
  - POST /api/orders/create: inaunda order (pending) + orderTimeline entry
  - POST /api/orders/transition: orderEngine.transitionOrder() + timeline
  - POST /api/orders/:id/timeline: historia ya hatua (orderTimeline collection)
  - GET  /api/orders/user/:userId: orders za mtumiaji

  FLOW YA SELLER QUOTE (lib/screens/orders/seller_quote_screen.dart):
    1. Mnumuzi anaunda order (pending)
    2. Muuzaji anaona kwenye seller_orders_screen -> seller_quote_screen
    3. Muuzaji anaweka shippingCost/quote -> order inakuwa 'quoted'
    4. Mnumuzi analipa (quoted -> paid) -> escrow_hold
    5. Dispatch -> confirmed (buyer anathibitisha) -> completed

  Frontend: order_flow_screen.dart (mwongozo wa hatua kwa hatua),
  order_detail_screen.dart (timeline ya order), my_purchases_screen.dart
  (ununuzi wa mnumuzi), seller_orders_screen.dart (orders za muuzaji),
  receipt_screen.dart (risiti na fallback logic).

  NOTE: Transactions na Orders ni mifumo miwili inayofanana — transactions ni
  mfumo wa sasa wa marketplace, orders/orderEngine ni mfumo mpya
  unaokua (seller quote flow).

6. MFUMO WA POCHI (WALLET SYSTEM) — Backend (server/index.js)
================================================================================

  Endpoints (zipo kwenye server; UI ya pochi ya mwisho inakua):

  - GET  /api/wallet/balance/:userId : salio (walletBalance)
  - GET  /api/wallet/history/:userId : historia
  - POST /api/wallet/delete-history  : futa historia

  Kwenye app: sellerBalance / pendingEscrow zinaonyeshwa kwenye
  seller_dashboard_screen na admin_user_detail_screen.

24. MTIRIRIKO KAMILI WA UNUNUZI (END-TO-END PURCHASE FLOW)
================================================================================

  1. Mnumuzi anabofya Buy Now (product_detail.dart)
  2. Checkout Screen: anachagua deliveryType (local/regional) + phone
  3. App inahesabu: totalAmount = bei + 3.5% commission + USSD fee
     (TransactionFeeBreakdown)
  4. clickpesa_service.initiateMarketplacePayment() -> POST
     /api/create-marketplace-payment-link
  5. Server inathibitisha: si suspended, si duplicate, daily limit (TZS 5M),
     rate limit. Pia inakokotoa resolveEffectivePrice(): ikiwa flash sale ipo
     active, inatumia salePrice (sio bei kamili kutoka client) kwa commission
     na totalAmount.
  6. Server inaita ClickPesa initiate-ussd-push-request
     (BillPay: calcGatewayFee kwa provider — M-Pesa/Airtel/Tigo 1%,
     HaloPesa 2%, CRDB 1%)
  7. ClickPesa inasukuma USSD -> mnumuzi anaingiza PIN ya mobile money
  8. ClickPesa inatuma webhook /api/clickpesa/webhook (HMAC)
  9. Server inasasisha transaction: status -> escrow_hold
     - platformFee 3.5% -> mapato ya Soko Vibe
     - pendingEscrow ya muuzaji += sellerReceives
     - totalSales++, grossSalesVolume += bei
     - revenue_transactions type 'sale'
  10. Arifa (OneSignal + in-app + SMS) kwa mnunuzi na muuzaji
  11. Muuzaji anasafirisha -> /api/escrow/dispatch (dispatchProof)
  12. Mnumuzi anapokea -> /api/escrow/release
      -> sellerBalance += sellerReceives
  13. Muuzaji anatoa pesa -> /api/seller/withdraw
      (amount + 2,000 payout fee) -> ClickPesa payout
  14. Ikiwa hakuna uthibitisho: auto-release baada ya siku 3 (local) /
      siku 7 (regional) kupitia cron ya saa 1
