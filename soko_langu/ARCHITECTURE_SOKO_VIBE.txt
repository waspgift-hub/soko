================================================================================
1. MUHTASARI WA JUU (HIGH-LEVEL)
================================================================================

Soko Vibe ni marketplace ya Tanzania: Flutter app (mobile/web) + Node/Express
server + Firebase + PostgreSQL + Redis + ClickPesa + OneSignal + Cloudflare.

Trafiki hupitia mlango mmoja wa umma:

  Mtumiaji (Flutter app / simu)
        |
        v
  api.sokovibe.co.tz  (Cloudflare Worker = edge cache + reverse proxy)
        |
        v
  soko-langu-server.onrender.com  (Render: API + Worker processes)
        |                  |
        |                  v
        |            PostgreSQL (Prisma)  <-- database kuu ya v2
        |            Redis (cache + queues BullMQ)
        v
  Sevices za nje (external services):
    - Firebase Auth / Firestore / App Check / Crashlytics / Performance
    - ClickPesa (malipo mobile money)
    - OneSignal (push notifications)
    - Meseji / Notify Africa (SMS)
    - Groq (AI assistant)
    - Cloudinary (legacy images) + Cloudflare R2 (media mpya)
    - Google AdMob (ad revenue)

MUHIMU: App ni HYBRID. Ipo katika mchakato wa migration kutoka v1 (Firestore
as source of truth) hadi v2 (PostgreSQL as source of truth). Kwa sasa zote
mbili zinaishi pamoja kwa make sure app yote inaendelea kufanya kazi:

  - v1 paths za app (orders, transactions, escrow, payouts, search,
    notifications, marketplace payment link) zinatumia FIRESTORE kupitia
    "legacy-compat" mounts kwenye server mpya.
  - v2 endpoints (/api/v1/*) zinatumia POSTGRESQL (Prisma) + Redis.
  - Maagizo mapya ya v2 yanajulikana Postgres na kisha "mirrored" kwenye
    Firestore ili Flutter app ya sasa isione tofauti.

Hii ina maana client haibadilishwi kabisa kwa sasa — mabadiliko ya migration
yanaishia server (+ cloudflare) tu.

  - Reconciliation window (FINANCE_RECONCILIATION_WINDOW_HOURS 24).
  - Dispute SLA (FINANCE_DISPUTE_SLA_HOURS 72).

4.6 Database config (src/config/database.js)

4.7 Authority stamps (client vs server)

  pendingEscrow/totalSales/grossSalesVolume/totalWithdrawn/isBoosted/
  boostedUntil/boostTier/kyc — Firestore rules zinakataa (noSensitiveFieldChanges).
  Server ndiyo mwenye mamlaka kwa financial/trust/kyc/boost fields
  (Admin SDK + Prisma). Hii ni defense against client-side tampering.

  statuses                -> statuses (msalaa)
  wishlist                -> (hai — wishlist iko device-local SharedPreferences)

  - helpers: isSignedIn, isOwner, isAdmin (users/{uid}.isAdmin==true),
    notSuspended.
  - noSensitiveFieldChanges / noSensitiveCreateFields: kukataa client kuandika

    totalWithdrawn, isAdmin, isSuspended, kyc, isBoosted, boostedUntil,

    reviewCount lazima 0; admin anaveza); update seller au bump viewCount/
    likedBy/rating/reviewCount/soldCount (admin).

    Firestore inline — updates zinapiganwa na status state machine; update
    hurejeshwa kwa soft-delete/shippingCost/totalAmount au admin.
  - Catch-all deny: /{document=**} -> allow read, write false.

firestore.indexes.json: 43 composite indexes (conversations, transactions,
  flash_sales, notifications, products, orders, chat_rooms, reviews, statuses,
  fraud_alerts, payouts, withdrawals, price_drops).

Firebase Auth: phone OTP (+255), email+password, email OTP, Google Sign-In.

  App Check: PlayIntegrity (prod Android), DeviceCheck (iOS). Debug token

Crashlytics: error reporting (native tu). Performance: metrics (native tu).
