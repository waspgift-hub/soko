1. PROJECT OVERVIEW
================================================================================

Soko Vibe is a full-stack e-commerce marketplace app for Tanzania. It connects
buyers, sellers, and riders (ride-hailing). The platform features:

- Product marketplace (buy/sell with KYC-verified sellers)
- Ride-hailing service (passengers ↔ drivers)
- AI shopping assistant (Groq LLM)
- In-app chat (1-on-1 + group)
- Mobile money payments (M-Pesa, Tigo Pesa, Airtel Money, Halopesa, EzyPesa)
- Escrow system with 14-day auto-release
- Product boost/promotion system
- Flash sales with barcode scanning
- "Natafuta Bidhaa" buyer requests
- Push notifications (OneSignal)
- Multi-language support (Swahili, English, Chinese)
- Admin dashboard with KYC, fraud detection, analytics

**Commission:** 3.5% charged to buyer at purchase. Seller receives full
(productPrice + shippingCost).

**Project ID:** sokonimoko-8c171-a8d14
**Package Name:** com.sokolangu.app

6. ARCHITECTURE
================================================================================

The app follows a 3-tier architecture:

  FLUTTER APP (Client)
    ↓ HTTP REST API
  EXPRESS.JS SERVER (Backend)
    ↓ Firebase Admin SDK
  CLOUD FIRESTORE (Database)

Key patterns:
- **Provider** for state management (ProductFeedProvider)
- **Repository pattern** for data access (AuthRepository, ProductRepository)
- **Service layer** for business logic (63 services)
- **GoRouter** for declarative navigation
- **Two-tier caching** (Redis distributed + in-memory LRU)

Data flow:
  1. User interacts with Screen widget
  2. Screen calls Service method
  3. Service calls Firestore directly OR calls Server API
  4. Server processes business logic, writes to Firestore
  5. Server returns response
  6. Service updates Provider/State
  7. Screen rebuilds with new data

7. AUTHENTICATION FLOW
================================================================================

Registration:
  1. User enters phone number
  2. Server sends OTP via Meseji/Notify Africa SMS
  3. User enters OTP, server verifies
  4. Firebase Auth account created with custom token
  5. ConsentRecordingService records clickwrap consent (device fingerprint,
     timestamp, IP, ToS/PP versions) → Firestore consentRecords + server
  6. Profile setup screen (name, location, etc.)

Login:
  Phone + OTP → Firebase custom token → Auth state updated
  Google Sign-In → Firebase credential → Auth state updated

Phone number variants stored:
  - Original input (e.g., "0712345678")
  - Clean digits ("712345678")
  - With country code ("+255712345678")
  All stored in users/{uid}.phoneVariants array for lookup.

Session:
  - Firebase Auth handles token refresh
  - SharedPreferences stores user profile locally
  - AccountManager supports multi-account switching

8. PAYMENT SYSTEM (CLICKPESA)
================================================================================

ClickPesa is the primary payment processor. Supports:

1. USSD Push (M-Pesa, Tigo Pesa, Airtel Money, Halopesa, EzyPesa)
   - Buyer dials USSD prompt on their phone
   - Confirms payment
   - Webhook callback confirms payment

2. BillPay (bank transfer)
   - Generates bill reference
   - Buyer pays via bank

3. Payout (disbursement to sellers)
   - Seller requests withdrawal
   - Server calls ClickPesa payout API
   - Webhook confirms payout status

Order reference format:
  - Product purchase: "product_{productId}_{timestamp}" (no underscores in final ref)
  - Boost: "boost_{boostId}_{timestamp}"
  - All references sanitized: .replace(/[^a-zA-Z0-9]/g, '')

Webhook security:
  - IP whitelist (CLICKPESA_ALLOWED_IPS)
  - HMAC signature verification (WEBHOOK_SECRET)
  - Idempotency lock via Redis (30s TTL)

Commission: 3.5% charged to buyer at purchase.
  - buyerPays = productPrice + shippingCost + commission
  - sellerReceives = productPrice + shippingCost
  - platformKeeps = commission

================================================================================
9. ESCROW & ORDER FLOW
================================================================================

State machine (server/orders.js):

  PENDING → BUYER_PAID → ESCROW_HOLD → DISPATCHED → DELIVERED → COMPLETED
                                    ↘ DISPUTED → RESOLVED
                                    ↘ CANCELLED (refund to buyer)

Auto-release: If buyer doesn't confirm within 14 days, escrow auto-releases
to seller. Cron job: POST /api/cron/release-escrows

Flow:
  1. Buyer pays → transaction created with status 'escrow_hold'
  2. Seller marks dispatched → status 'dispatched'
  3. Buyer receives → confirms delivery → status 'completed'
  4. ClickPesa payout to seller's mobile money

Dispute:
  1. Buyer raises dispute → funds stay in escrow
  2. Admin reviews evidence
  3. Admin resolves → release to seller OR refund to buyer

12. SECURITY MEASURES
================================================================================

1. SSL PINNING
   - Real SPKI hashes from live cert chains (not placeholders)
   - Primary + backup (intermediate CA) pins for each service
   - Services: Render, Firebase, Cloudinary, OneSignal
   - Expiry: 2027-08-18
   - Cleartext traffic blocked

2. R8 OBFUSCATION (Android Release)
   - isMinifyEnabled = true
   - isShrinkResources = true
   - proguard-rules.pro: log stripping, repackageclasses, anti-RE

3. FIRESTORE FIELD-LEVEL PROTECTION
   - noSensitiveFieldChanges() blocks client writes to:
     walletBalance, sellerBalance, pendingEscrow, totalSales,
     grossSalesVolume, totalWithdrawn, isAdmin, isSuspended,
     kyc, isBoosted, boostedUntil, boostTier, createdAt, etc.

4. WEBHOOK SECURITY
   - IP whitelisting (ip-range-check)
   - HMAC signature verification
   - Idempotency lock via Redis (30s TTL)

5. RATE LIMITING
   - 30 req/min general per IP
   - 5 req/min for payments per IP
   - In-memory sliding window with 5-min sweeper

6. CLICKWRAP CONSENT
   - ConsentRecordingService captures device fingerprint
   - Records: userId, deviceId, acceptedAt, ipAddress,
     tosVersion, ppVersion, platform, appVersion, deviceInfo
   - Stored in Firestore consentRecords + server /api/consent/record

7. PROFANITY FILTER
   - safe_text package (Swahili language)
   - Applied to reviews, comments, replies, chat messages
   - 3-strike escalation policy

8. FRAUD DETECTION
   - Automated fraud alerts for suspicious patterns
   - Seller risk scoring
   - Device fingerprinting for banned users

9. APP CHECK
   - Firebase App Check enabled (device attestation)
